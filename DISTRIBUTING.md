# Distributing Ariadne

Releases are cut from GitHub Actions. Pushing a version tag builds
unsigned artifacts for macOS, Windows, and Linux and attaches them to a
GitHub Release.

## Cutting a release

1. Bump the version in `app/Cargo.toml` (and `Cargo.lock` via `cargo build`).
2. Commit and push to `main`.
3. Tag and push the tag: `git tag v0.2.0 && git push origin v0.2.0`.
4. Watch the `release` workflow; when green, the GitHub Release page has:
   - macOS: `ariadne-<arch>.dmg` containing `Ariadne.app`
     (arm64 + x86_64; unsigned — right-click → Open on first launch)
   - Windows: `ariadne-x86_64-pc-windows-msvc.zip` with `ariadne.exe`
     (SmartScreen will warn — "More info" → "Run anyway")
   - Linux: `ariadne-<arch>.deb` plus a portable `.tar.gz`
     (installs binary, icon, and `.desktop` entry)
5. Smoke-check each artifact: install/launch, confirm the library window
   draws (CI already runs the `--screenshot` smoke test per artifact).

## How it works

- [`cargo-dist`](https://opensource.axo.dev/cargo-dist/) reads
  `[workspace.metadata.dist]` in `app/Cargo.toml` and builds one archive
  per target triple. `cargo dist plan` (run locally) previews the layout.
- `.github/workflows/release.yml` is generated by
  `cargo dist generate-ci github` — do not hand-edit the generated parts;
  regenerate after changing dist config.
- `deny.toml` (`cargo-deny`) audits dependency licenses on every PR so the
  tree stays MIT-compatible. Adding a copyleft dependency fails CI.

## Local release builds

```sh
cd app
cargo dist build --artifacts=all   # needs target toolchains per OS
```

macOS-only DMG from this Mac:

```sh
cd app
cargo dist build --target=aarch64-apple-darwin
```

## Future: signing

Artifacts are currently unsigned. When ready:

- macOS: Apple Developer ID + `cargo-dist` `macos-sign` settings, then
  notarization (`notarytool`) to silence Gatekeeper.
- Windows: Authenticode cert (SSL.com/Sectigo) wired into the workflow;
  silences SmartScreen after reputation builds.
- Linux: GPG-sign the `.deb` / checksums file.

No code changes are needed for any of the above — signing is config +
secrets only.
